# Day 29: The Complete Project

## What this is

A RAG system built entirely from scratch over 28 days, now wired into
one clean, runnable whole. Every piece, chunking, embeddings, a vector
store, retrieval, ranking, generation, caching, validation, security
checks, and monitoring, is a real, working component built earlier in
this project, imported here rather than rewritten. Nothing in this
folder copies code from an earlier day: it imports it.

## The folder map

- **Foundations** (Days 1 to 4): keyword search, embeddings, a vector
  database, and chunking, the raw material every later stage builds on.
- **Retrieval and ranking** (Days 5 to 6, 9 to 13): finding candidate
  chunks and putting the best ones first, plus query rewriting,
  embedding model choices, scaling, context budgets, and hallucination
  checks.
- **Generation** (Day 7): turning ranked chunks into a sourced, readable
  answer.
- **Evaluation** (Day 8, 21, 26): real precision, recall, NDCG, and MRR
  metrics, agent evaluation, and A/B testing, so "better" always means
  something measured, not assumed.
- **Production** (Days 14, 22 to 26): caching, a production service, an
  HTTP API, monitoring, edge case handling, and domain adaptation.
- **Security** (Days 15 to 20, 27): agents and tool use, plus prompt
  injection checks, PII redaction, and access control.
- **Adaptation** (Day 28): adjusting the toy system to a real domain
  using labeled feedback, measured on held-out data.

## How to run the whole system

From this folder:

    python main.py

That builds the complete pipeline, answers three sample questions with
their sources, prints the service's health and key metrics, and tells
you how to run the test suite.

## How to run the tests

    python tests.py

The whole suite runs in a few seconds, covering config validation,
request validation, retrieval correctness, access control, prompt
injection detection, PII redaction, safe error handling, and the
empty-index case.

## What this system does not do, and why that is honest

This project uses toy embeddings (a small, hand-built set of word
concepts, not a real trained model), a toy vector store (a Python list
with cosine similarity, not a real indexed database), and no real
language model (answers are built with templates and real retrieved
text, never generated by an LLM). None of this is pretending to be
production-grade AI. It is honest, working code that demonstrates
exactly how every piece of a real RAG system fits together, at a scale
anyone can read, run, and understand in an afternoon, with no API key,
no GPU, and no internet connection required.

## What to build next

Swap the toy embedding function for a real embedding model (Day 9
covers how to choose one), swap the toy vector store for a real one
(Day 3's comparison covers the options), and connect a real language
model to the generation stage (Day 7's prompt engineering and Day 19's
function calling both show where that would plug in). Everything else
in this project, the validation, the caching, the security checks, the
monitoring, the evaluation discipline, carries over directly to that
real system unchanged.

## The finished house analogy

A house built room by room, floor by floor, over many weekends, is
still just a pile of separate rooms until someone connects the
plumbing, wires the electricity through every floor, and hangs a floor
plan on the front door so a visitor can actually find their way around.
Days 1 through 28 built every room: the foundation, the retrieval
pipeline, the generation stage, the production hardening, the security
layer. Day 29 is that final connection, one front door (`main.py`), one
floor plan (this README), and a single command that proves every room
actually works together as one house, not just as a collection of
rooms built next to each other.
