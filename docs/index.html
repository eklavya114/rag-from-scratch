What this is

Three ways to describe the same project

Pick the one that matches what you are looking for.

A complete RAG pipeline

Chunking, embeddings, a vector store, retrieval, ranking, and generation, each one built and tested before the next is layered on top.

A production hardening course

An honest learning project

What you will learn

Outcomes, not topics

Measure retrieval quality before trusting it
Build an agent that plans, acts, and recovers from failure
Tell a real difference from random noise with a significance test
Catch a prompt injection attempt before it reaches a model
Serve a RAG pipeline over real HTTP, with real status codes
Redact personal data before it ever reaches a log file
Spot overfitting by comparing train and held out scores
Wire 29 separate pieces into one tested, runnable system
Honest limits
Toy embeddings. A small, hand built concept vocabulary, not a trained model.
No real LLM. Answers come from templates filling in real retrieved text.
No real vector database. A Python list scored with cosine similarity, not an indexed store.
Not a security audit. The security work here is real teaching material, not a certified review.
Quick start

Running in under a minute

Python 3.10 or newer. Nothing else.

1

Clone the repository.

git clone https://github.com/eklavya114/rag-from-scratch
2

Enter the complete system and run it.

cd rag-from-scratch/day-29-complete-system && python main.py
3

Run the test suite.

python tests.py
By week

What each week leaves you able to do

Week 1

Foundations

  • Explain retrieval, ranking, and generation separately
  • Turn text into embeddings and search them
  • Generate a sourced answer from retrieved chunks
Week 2

Production Quality

  • Score retrieval with precision, recall, and NDCG
  • Scale a pipeline from 100 to 100,000 documents
  • Cache results and measure the real speedup
Week 3

Agents

  • Build an agent loop with tools and memory
  • Make reasoning explicit with the ReAct pattern
  • Plan multiple steps ahead and replan on failure
Week 4

Shipping

  • Serve a RAG service over a real HTTP API
  • Run an A/B test and check for statistical significance
  • Ship one tested, documented, complete system
